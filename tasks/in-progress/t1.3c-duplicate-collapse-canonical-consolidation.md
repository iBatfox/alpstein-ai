# Phase 1.3C — duplicate collapse and canonical source consolidation

**Status:** ready (docs-only consolidation)  
**Date:** 2026-05-27

---

## Goal

Collapse overlapping documentation and define **one canonical source per topic** without changing runtime behavior or redesigning architecture.

---

## Overlap clusters (to resolve)

- Project status: `current-state.md`, `completed.md`, `next-steps.md`, `engineering-archive.md`, topology/audit docs
- Architecture summaries: canonical runtime map vs runtime-derived supplements vs legacy drafts
- Audits: engineering audit report vs topology report vs current-state snapshot
- Conversational behavior: intent policy, greeting, pre-sales legacy notes, governance hierarchy
- PromptBuilder rules: spec (`specs/architecture/prompt-builder-rules.md`) vs notes/drafts
- n8n workflow state: repo exports vs ops runbooks vs historical plans
- Telegram ingress docs: workflow runbook vs mapping appendix
- Langfuse docs: canonical runtime map §11 vs runtime-derived tracing doc

---

## Rules / constraints

- No runtime changes.
- No architecture redesign.
- Do not rewrite canonical docs into new formats.
- Preserve historical evidence where useful.
- Prefer **banners + cross-links** over prose rewrites.
- Remove duplicated summaries only when they are clearly stale copies and not historical evidence.

---

## Outputs

- Canonical doc list per topic
- Deprecated duplicate list
- Historical reference list
- Remaining overlap risks
- Recommended commit message (no commit until review)
