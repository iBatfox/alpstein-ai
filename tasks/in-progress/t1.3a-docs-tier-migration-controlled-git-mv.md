# Phase 1.3A — controlled git mv documentation migration

**Status:** ready (docs-only migration)  
**Date:** 2026-05-27  

---

## Goal

Move documentation into the tier directory structure safely using `git mv` (preserve history), and update internal relative links/indexes/topology references so the new tier paths become discoverable.

---

## Scope (Phase 1.3 low-risk batch)

Perform **path-only** moves (no content rewrites), leaving minimal stub redirect files at the old locations (no deletions yet).

Move these documents into the new tier structure:

1. `docs/project-status/backlog.md` → `docs/project-status/historical/backlog.md`
2. `docs/project-status/t11-prompt-builder-design.md` → `docs/architecture/deprecated/t11-prompt-builder-design.md`
3. `docs/project-status/t11-ai-orchestration-plan.md` → `docs/project-status/historical/t11-ai-orchestration-plan.md`
4. `docs/project-status/t12-lead-notification-plan.md` → `docs/project-status/historical/t12-lead-notification-plan.md`
5. `docs/project-status/engineering-audit-report.md` → `docs/project-status/historical/engineering-audit-report.md`

---

## Requirements / constraints

- Use `git mv` only for relocating existing documents (preserve git history).
- Do not delete files yet; replace each old-path file with a minimal stub redirect that points to the new tier path.
- Update relative links / indexes / topology references that point to the moved old paths.
- No backend changes, no n8n changes.
- No broad docs rewrite; update only what breaks or becomes incorrect due to moved paths.
- After migration, run a link sweep to surface unresolved old-path references.

---

## Risks

- Broken relative links inside moved documents if they reference sibling paths by relative directory assumption.
- Stale index/table entries pointing at legacy flat paths.
- Skill/reference docs that embed absolute/relative links to legacy paths.

---

## Tests / verification (docs-only)

1. `rg` sweep for the moved old paths across `docs/`, `tasks/`, and `.cursor/skills/`.
2. Confirm moved files exist at the new paths.
3. Confirm stubs exist at old paths.

---

## Out of scope (for later phases)

- Moving runtime-derived architecture docs under `docs/architecture/runtime/` or ops runbooks under `docs/ops/*`.
- Any conversational cluster moves (Phase 1.4).
- Deleting deprecated/original content.
