Required behavior:

1. Duplicate incoming message
- if save_result.is_duplicate is true:
  - do not create lead
  - do not update lead
  - notify_owner=false
  - lead_created=false
  - lead_updated=false
  - notification omitted/None
  - keep existing duplicate AI reply behavior from T11.14

2. Non-duplicate first customer message / no active lead
- find active lead using LeadService.find_active_lead
- if none:
  - create lead
  - lead_created=true
  - lead_updated=false
  - include lead summary in response
  - notify_owner decided by NotificationPolicyService

3. Non-duplicate follow-up with active lead
- update active lead
- lead_created=false
- lead_updated=true
- include lead summary in response
- lead_updated only should normally not notify unless urgent/handoff/ai_failure

4. Tenant/context safety
- before create/update lead, validate business/customer/conversation tenant/business consistency
- do not rely only on UUIDs
- all lead operations must use tenant_id + business_id

5. Signal detection
- run LeadSignalDetectionService on customer message text
- use urgent_detected and handoff_requested as inputs to NotificationPolicyService
- if urgent_detected:
  - lead priority should become urgent
- if handoff_requested:
  - notification policy should produce human_handoff

6. AI failure input
- ai_failed should be true only when the actual reply_to_customer came from fallback due to AI failure
- do not mark ai_failed for duplicate safe acknowledgment
- do not mark ai_failed for successful AI response

7. Notification policy input mapping
- pass:
  - is_duplicate
  - lead_created
  - lead_updated
  - urgent_detected
  - handoff_requested
  - ai_failed
- do not pass both lead_created and lead_updated as true for the same message

8. Response mapping
- top-level notify_owner must equal notification.should_notify_owner when notification object exists
- omit notification when should_notify_owner=false
- include:
  - lead_created
  - lead_updated
  - lead summary id/status/priority
  - optional notification object
- do not expose internal AI/final_prompt/raw_payload/system_prompt data

9. Route
- route remains thin
- commit/rollback remains route-owned

Tests:
- duplicate skips lead create/update and notification
- first non-duplicate creates lead and notify_owner=true with new_lead
- follow-up updates active lead and notify_owner=false when routine
- urgent message sets lead priority urgent and notification urgent_lead
- handoff message returns human_handoff notification
- AI fallback failure returns ai_failure notification
- lead_created and lead_updated are never both true
- notification omitted when should_notify_owner=false
- tenant/context mismatch raises TenantContextError or fails safely
- route response envelope includes new fields and hides internal fields
- no n8n/provider/OpenAI changes/imports
